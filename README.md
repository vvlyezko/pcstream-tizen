# PC Stream

Трансляция экрана компьютера со звуком на телевизор Samsung (Tizen) по домашней сети:
по кабелю, по Wi‑Fi или вперемешку. Две программы: **PC Stream** для Windows и
**PC Stream** для телевизора.

- **Источник:** весь экран или отдельное окно. Окно транслируется, даже если его закрыли
  другими окнами.
- **Видео** кодирует видеокарта NVIDIA (FFmpeg + NVENC, HEVC): 1440p60 и 4K60 без нагрузки
  на процессор.
- **Звук** — весь системный, в стерео. Его можно одновременно слушать на ПК и на ТВ или
  заглушить на ПК.
- **HDR на ПК не выключается.** Трансляция идёт в SDR, сам компьютер остаётся в HDR.
- **Задержка** около 0,5 с, звук автоматически синхронизируется с картинкой.
- **Телевизор сам находит компьютер** в своей сети и, если есть, подключается по кабелю.
- **Интерфейс** со «стеклянным» эффектом на обеих сторонах.

> Встроенный в телевизор «Screen Mirroring» (Miracast) работает через прямое Wi‑Fi‑соединение:
> телевизору приходится отключаться от роутера, а звук уходит только на ТВ. PC Stream работает
> через обычную домашнюю сеть.

## Требования

| | |
|---|---|
| ПК | Windows 10 (2004+) или 11, видеокарта NVIDIA GeForce GTX 950 и новее (NVENC HEVC) |
| Телевизор | Samsung на Tizen 5.5+ (модели 2020 года и новее). Проверено на QE55Q95T |
| Сеть | ПК и ТВ в одной локальной сети. Для 4K и высокого битрейта лучше кабель |

## Установка на ПК

1. Скачайте `PC-Stream-Setup-<версия>.exe` в разделе [Releases](../../releases) и запустите.
   Установка в один клик, права администратора не нужны. Ярлыки появятся на рабочем столе
   и в меню «Пуск».
   Если нужен вариант без установки — `PC-Stream-<версия>-portable.exe`.
2. Программа не подписана сертификатом разработчика, поэтому Windows SmartScreen может
   показать «Windows защитила ваш компьютер». Нажмите **Подробнее → Выполнить в любом случае**.
3. При первом запуске Windows спросит про доступ к сети. Разрешите доступ в **частных сетях**,
   иначе телевизор не увидит компьютер. Сервер слушает порт **8787**.

## Установка на телевизор

Samsung разрешает ставить свои приложения только в режиме разработчика с подписью сертификатом
Samsung. Настройка делается один раз.

1. **Tizen SDK.** В VS Code установите расширение **Tizen Extension**
   (`code --install-extension tizen.vscode-tizen-csharp`). При первом запуске укажите путь
   без пробелов и кириллицы, например `C:\tizen-studio`. В **Package Manager** доустановите
   **Samsung Certificate Extension** и **TV Extensions**.
2. **Режим разработчика.** На ТВ: **Smart Hub → Apps** → наберите **1 2 3 4 5** → включите
   **Developer mode** → впишите IP компьютера → **OK** → перезагрузите телевизор.
3. **Подключение.** В терминале выполните `C:\tizen-studio\tools\sdb.exe connect <IP телевизора>`.
4. **Сертификат.** Tizen → **Certificate Manager** → новый профиль типа **Samsung** →
   distributor уровня **Public** с DUID телевизора. Сделайте профиль активным.
5. **Сборка и установка.** В папке проекта выполните:
   ```bash
   powershell -ExecutionPolicy Bypass -File tools\build.ps1 -TvIp <IP телевизора>
   ```

Подробности и решение проблем с подключением и сертификатом — в инструкции соседнего проекта
[KinoPub для Tizen](https://github.com/vvlyezko/kinopub-tizen#установка-на-телевизор):
шаги там те же.

**Поделиться приложением для ТВ.** Выполните `tools\build.ps1 -Unsigned`, получится
`dist\PCStream-unsigned.wgt`. Получатель подписывает его своим сертификатом:
`tools\build.ps1 -Wgt PCStream-unsigned.wgt -TvIp <IP>`.

## Как пользоваться

1. На ПК откройте **PC Stream**, выберите **Весь экран** или **Отдельное окно** и нажмите
   **Начать трансляцию**.
2. На ТВ откройте **PC Stream**: компьютер появится в списке. Выберите его, нажав OK.
   Последний компьютер запоминается, и при следующем запуске приложение подключится само.

### Настройки на ПК

| Настройка | Варианты | Совет |
|---|---|---|
| Разрешение | Исх., 1440p, 1080p, 720p | Для Wi‑Fi — 1080p |
| Частота кадров | 30, 60 | 60 — для игр и видео |
| Битрейт | 10, 20, 30, 45 Мбит/с | Wi‑Fi — 10–20, кабель — 30–45 |
| Курсор, звук, заглушить звук на ПК | вкл/выкл | |

### Пульт телевизора

| Кнопка | Действие |
|---|---|
| ↑ ↓, OK | Выбор компьютера, подключение |
| OK / ↑ / ↓ во время показа | Панель: статистика, синхронизация звука, отключение |
| ◀ ▶ на «Синхронизация звука» | Сдвинуть звук на ±20 мс |
| Назад | Скрыть панель, отключиться, выйти |

### Проблемы

- **Телевизор не находит компьютер.**
  - ПК и ТВ должны быть в одной сети.
  - Проверьте, что в брандмауэре Windows PC Stream разрешён для частных сетей, а сама сеть
    в Windows отмечена как частная.
  - Убедитесь, что адрес отвечает: откройте `http://<IP ПК>:8787/info` в браузере телефона.
- **Подтормаживает.** Подключите ТВ кабелем или уменьшите разрешение и битрейт.
- **Звук опережает или отстаёт.** Подстройте кнопкой «Синхронизация звука».
- **Трансляция прервалась при запуске игры или включении HDR.** Захват экрана перезапускается
  сам, обычно за секунду.

## Сборка из исходников

Нужны Node.js 20+ и Windows.

```bash
cd pc
npm install
powershell -ExecutionPolicy Bypass -File ..\tools\prepare.ps1   # FFmpeg и winlist.exe в pc\bin
npm start                                                       # запуск без сборки
npm run dist                                                    # установщик и portable в pc\dist
```

`prepare.ps1` скачивает FFmpeg из [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds):
он весит около 170 МБ и в репозиторий не входит. Скрипт также собирает `winlist.exe` из
`pc/native/winlist.cs` компилятором .NET Framework, который уже есть в Windows.

Приложение для телевизора (`tv/`) — чистый JavaScript без сборки, совместимый с Chromium 69
(Tizen 5.5). Его можно открыть в браузере: `python -m http.server 8091 --directory tv`.
Он найдёт ПК по `localhost`.

## Как это устроено

```
ПК (Electron)                                         Телевизор (Tizen web app)
 экран: ddagrab ─┐
 окно: gfxcapture ┴→ FFmpeg hevc_nvenc → FLV → свой fMP4-муксер ─┐
 звук: getDisplayMedia (loopback) → AudioWorklet → PCM 48 кГц ───┴→ WebSocket :8787 ─→ MSE  (видео)
                                                                                    └→ AudioWorklet (звук)
```

- **ПК** (`pc/`): `src/capture.js` — FFmpeg, `src/media.js` — разбор FLV (в том числе enhanced
  FLV для HEVC) и сборка фрагментов fMP4, `src/server.js` — HTTP и WebSocket без зависимостей,
  `src/sources.js` — экраны и окна.
- **Телевизор** (`tv/`): `js/app.js` — поиск ПК, MSE-плеер и контроль задержки,
  `js/pcm-player.js` — непрерывное воспроизведение звука.

### Особенности Tizen 5.5, найденные на реальном телевизоре

- MSE декодирует H.264 только до 1080p, а 1440p даёт ошибку декодера. HEVC работает
  в 1440p60, 10 бит и 4K60, поэтому по умолчанию используется HEVC.
- Политика безопасности по умолчанию (`default-src *`) не пускает `blob:`. Без явного
  `media-src blob:` в `config.xml` MSE-видео не запускается.
- Смена `playbackRate` на ходу вешает аппаратный плеер, а перемотка округляется до
  предыдущего ключевого кадра. Поэтому задержка снижается прыжком ровно на свежий ключевой кадр.
- Звук отдельными `AudioBufferSourceNode` по 20 мс в Chromium 69 искажается на стыках. Здесь
  он идёт через AudioWorklet с кольцевым буфером и плавной подстройкой скорости.
- AudioWorklet не загружается из `file://`, поэтому модуль подключается через `blob:`.
- `webapis.network.getIp()` работает не на всех прошивках. Свой адрес телевизор узнаёт ещё
  через `tizen.systeminfo` и WebRTC.

### Особенности Windows и Chromium

- Если выход AudioContext долго молчит, Chromium в скрытом окне подменяет звуковой вывод
  таймером, и терялась треть звука. Выход держится «не тихим» неслышимым сигналом.
- Захват звука через getDisplayMedia по умолчанию включает обработку для звонков: моно,
  шумоподавление и автоусиление. Здесь она отключена.
- `desktopCapturer.getSources` с миниатюрами окон течёт памятью, поэтому окна перечисляет
  `winlist.exe`, а миниатюры делает FFmpeg.
